Admin Guide: Pre-Registering 30 Vehicles & Key Drivers and Initial Setup

This official guide uses item-by-item infographics to walk administrators through the entire process before system launch: collecting ① initial data for all 30 company vehicles and ② the pre-approved roster of key drivers (employees), then bulk-entering and managing them in the Admin Console (security PIN).

ITEM 01 4-Step Master Roadmap for Admin Preparation & Initial Setup

Total time: approx. 30 min (one-time)

Instead of installing dashcams or OBD devices in the vehicles, the admin registers the basic vehicle data (Bluetooth MAC · odometer reading) and the key driver roster via CSV just once. From then on, every dispatch, tracking event, and mileage logbook entry is 100% automated.

ITEM 03 Collecting & Bulk-Registering Key Driver (Employee) Information

Supports individual add & bulk CSV upload

The admin collects 5 basic data points for each department's key drivers who will operate company vehicles, and registers them in the system in advance. Only pre-registered drivers can submit dispatch requests and use 1-second QR self-checkout; unregistered users and drivers with suspended dispatch rights (dispatchAllowed = N) are blocked automatically.

[Infographic 03] Flow: collect key driver roster → register in Admin Console → real-time permission heartbeat monitoring

💡 Name Entry Tip for Bilingual (KOR/ENG) Display

If you enter each driver's name as Korean name + English name in parentheses, e.g. Sunghoon Park (Dave Park) with the Korean name written in Hangul, the name appears in Korean when KOR is selected in the top menu and automatically switches to Dave Park when ENG is selected.

🚫 Using the Dispatch Permission Flag (dispatchAllowed)

For drivers who belong on the roster but whose license has not yet been verified or who have not completed training, set dispatchAllowed to N in the CSV. They will be registered on the roster, but their vehicle dispatch requests will start in a locked (blocked) state.

ITEM 05 Weekly Check After Launch — Odometer Reconciliation & Ghost Trip Audit

Recommended: once a week

Even if an employee deliberately turns off smartphone Bluetooth or GPS and drives a vehicle off the record, once a week the admin enters the actual vehicle odometer reading and clicks [Reconcile Odometer]; the system then automatically flags the unrecorded mileage (+5 km or more) and the likely suspect.

[Infographic 05] Automatic Ghost Trip detection via weekly odometer reconciliation (discrepancy of +5 km or more)

ITEM 06 Record Keeping & Monthly Operations on Microsoft 365 (SharePoint · OneDrive Excel · Teams)

No external DB (Supabase) — runs on the company M365 tenant

The web app is the live operations ledger ("who is driving which car right now"); Microsoft 365 is the archive ledger ("where is last month's trip log"). Once a week the admin uses CSV Export in the Admin Console, uploads the files to SharePoint, and merges them into the Excel master once a month. No database subscription or Azure app registration is required.

JSON DB backup · security rules
  • Copy the server's data/fleet-db.json weekly → upload to SharePoint Backup/ (never keep it inside an OneDrive sync folder)
  • The admin PIN lives only in the server env var FLEET_ADMIN_PIN; never post it in Teams or documents
  • DB Reset works only after PIN verification (unauthenticated API calls get 401)
  • Trip-log CSVs contain no phone numbers (employee CSVs stay in Master/, admin-only)
  • Retain backups and trip records for 7 years
